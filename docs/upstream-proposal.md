## 建议的首个讨论问题

新 Rust 核心准备怎样承载同一份调色参数，使桌面/浏览器预览和 headless 导出具有相同算子语义？我们希望先贡献一个小的、可测试的调色基础，而不是提前定义新的插件系统。

## 为什么现在讨论

主线编辑页和预览仍是占位，README 中的 Editor API、插件、Rust 核心和 headless 是未来方向。此时可明确颜色域、参数与测试的基础约定，减少以后分开实现预览/导出产生的差异。[README](https://github.com/OpenCut-app/OpenCut/blob/e668010778568641babef2cc40be4703ae6916d6/README.md)、[编辑占位](https://github.com/OpenCut-app/OpenCut/blob/e668010778568641babef2cc40be4703ae6916d6/apps/web/src/routes/editor.tsx#L3-L12)、[预览占位](https://github.com/OpenCut-app/OpenCut/blob/e668010778568641babef2cc40be4703ae6916d6/apps/desktop/src/panels/preview.rs#L5-L20)

## 最小拟议贡献

第一块只覆盖已明确颜色约定的 RGB 数据、旁路和曝光计算，配解析样例及故意错误操作的反例。它不依赖 UI、文件系统或插件注册；未来扩展必须以实际宿主接口为依据。

输入域、浮点精度、alpha 规则、处理位置及参数持久化先商定。crate 名称、公开 ABI、插件格式和 Rust/WASM 边界均不在本草案中提前固定。

## 验收建议

- 默认值/旁路保持输入，曝光符合解析值。
- 重复处理及参数序列化具有确定语义。
- 将来预览和导出共用计算及参数快照；端到端视频另验。
- 新依赖有明确构建成本、版本与许可证；首个切片尽量避免新依赖。
