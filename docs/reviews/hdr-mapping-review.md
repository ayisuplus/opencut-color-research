# HDR Global 映射与校准准入：独立对抗审查

日期：2026-10-13（Asia/Shanghai）。本次审查只读截图、原生 DRX、保存/导出回执、映射报告、固定二进制片段及候选 grade 生成器。只写本文件；没有调用 Resolve、MCP、SDK 或目标代码，没有修改 grade、配置或工程，也没有下载工具或重算目标大文件摘要。

**最新结论：本轮六帧有界原生对照已通过独立 EXR 文件及整幅像素复算，当前没有未关闭的必须修改项；完整 UI 换算与内部曝光算法仍未证明。** 校准与执行增量见末节。下面保留候选准备阶段的初审记录，其中“0 帧”“未准入”和待补见证属于当时状态。

**初审结论（候选准备阶段）：三个候选 grade 可进入指定实验副本中的原生 Apply、UI 显示及再导出读回校准探针；当时尚未准入正式 HDR −1/0/+1 像素对照。** 没有必须修正的生成器缺陷。结构合法和单字段修改不保证宿主接受，更不证明控件单位或像素公式。

## 已独立确认的证据

- 已直接查看用户截图：Global 曝光显示 1.00、饱和度 1.00、X/Y 0.00。截图是控件裁剪，单独不能证明工程、节点或当前帧身份；这部分由原始捕获回执和用户操作上下文关联。零点来源为用户直接确认显示 0.00，本轮没有相应零点截图。
- 两个原生 grade 的长度及 SHA-256 与映射报告一致。保存/导出原始回执成功，守卫针对 21.1.1.10、Disk 测试库、EXPO_003_HDR_MAPPING、指定时间线、单层及单节点。没有把工具正文错误当作成功。
- 独立从此前已记录的两份 descriptor 偏移读取 2917/6309 字节并核对摘要；重建所需类型定义，以独立 Node 读取器处理 protobuf 边界、wire/type、packed 数值、嵌套消息、required、oneof 及唯一目标。使用 Node Zstandard 在内存解压，没有执行目标或沿用生成器的字串定位作为类型依据。
- 两个人工样本的 Body0/Body1 均为 284/142 字节，独立解释字段数为 86/35。实际目标是 key `0x86000305` → HDR value #16 → 唯一 Global → `gainjz` float32。显示 1.00 的内部值为 `1.003199815750122`；显示 0.00 的内部值为 `0.004799820948392153`。
- 按已解码叶字段独立比较，Body0 除 `lastmodtime` 外只有上述 `gainjz` 变化；Body1 只有 `lastmodtime` 变化。未把重复列表下标当成参数身份。

整个 DRX 不能据此称为“只差一个曝光值”。排除 Body 后，两次人工抓 still 的外层仍有对象标识、CreateTime、Buffer 和 ClipThumbnails 差异；它们分别为 19,780/18,832 字节。当前映射报告把单字段差异限定在已解码 Body，表述准确。

## 反例与结论限制

1. **显示零不等于精确零或旁路。** 零点 grade 仍显式保存非零 `gainjz`，并标 HasCorrection=true；原 neutral 没有这一 HDR 分支。三者必须分别命名和保存，不能将任一个默认为另一个。
2. **两个有限精度点不能确定公式。** 内部数值差约 0.9984。控件值直接存储但显示舍入/鼠标量化，以及带偏移的转换，都能与这两个显示点相容。没有依据选择其中一种，也没有 −1 的人工样本作为现有映射证据。
3. **字段名不能确定操作域。** `gainjz`、float32 值、HDR #16 和控件显示的关联，不提供线性 RGB 倍率、Jz 算法、EV 换算或最终渲染公式。CDL/OCIO 的结果不能补这项缺口。
4. **项目颜色设置不能替代 palette 上下文。** 官方域研究分别记录 HDR palette Color Space/Gamma 和 Black Offset；SDK 项目 timeline 设置没有被证明就是这些菜单值。当前裁剪截图也没有包含它们。

公开样本应先称“Global UI 显示档位”和“再导出的内部 float32 值”。即使 UI 显示为 −1.00/0.00/+1.00，也不能将两位小数当作无限精度的控件读数，或直接承诺线性光量倍增。

## 候选生成器与允许的下一步

[prepare-hdr-stored-values.py](../../experiments/prepare-hdr-stored-values.py) 限定同一原生源 SHA-256，唯一查找目标 key/value、#16、Global 和原值，再替换四字节 float32。它不调用 SDK；输出使用新文件并拒绝覆盖，未把文件名当作已确认的原生档位。其字串定位依赖这个固定快照，不应去掉 source 摘要约束后当作通用 DRX 编辑器。

三个实际候选文件已独立解压、按类型重读及核对摘要，得到内部值 −1.0、+0.0、+1.0。目标 payload 确位于 Body0 的 `[147,151)` 半开区间。区间之外的解压字节完全保持；Body1 的压缩/解压字节及 Body0 hex 之外的外层原字节完全保持。显式 +0.0 是合法 float32 wire 值，不能以 proto3 的缺省规则将它与省略分支混淆。

候选仍保留原始 +1 still 的 thumbnail、对象标识和其他外层数据，这是最小修改策略的一部分；这些旧缩略图不能充当新档位的画面证据。独立验证记录也明确没有建立 NativeApply 接受、UI 映射或像素效果。

已读 `apply-stored-minus1.py`：版本、库、工程、时间线、单层/单节点守卫后，仅调用指定 grade 的 Apply、打开 Color 页、定位固定帧及保存；没有渲染或全局删除/停止接口。脚本明确 `UI_confirmed_by_this_script=False` 和 `rendered_by_this_script=False`。因此可进入这个校准探针。Apply 返回 False、节点/上下文异常或读回不匹配时，应保留失败阶段并停止后续档位/渲染，不把结构检查通过改写成宿主成功。

正式三档对照仍需完成以下准入条件：

1. 每一档在同一指定副本、clip/version、单层单节点、固定帧下原生应用；保存能够关联该上下文的 UI 显示证据，不能只复用现有 +1 裁剪。
2. 每一档重新原生 GrabStill/Export，独立按 key、HDR branch、Global 身份核对实际 `gainjz`。精确 stored −1/0/+1 应分别读回相应 float32；同时核对其余调色参数、分支、节点身份没有额外变化。原生生成的时间戳/缩略图等另列，不作为忽略未知参数变化的借口。
3. 固定并记录 HDR palette Color Space/Gamma、Black Offset、其他 Global 控件，以及支持的项目/时间线/素材颜色设置。缺失项保留未知，不能据继承或菜单默认值写成实测。
4. 将原 neutral、人工显示零点和候选内部精确零分别保留。之后的像素对照使用真实渲染和独立读取，先说明比较的是哪一条基准；当前还没有这些渲染结果。

## Qt 静态入口的证明限度

四个 raw 代码窗口的摘要与 manifest 一致，并独立逐字节比对固定新版 Resolve.exe 对应 RVA：合计 114,688 字节，另读取 PE 头；没有重新扫描或计算整个目标的摘要。

Qt 控制器元数据的 index 6 为 `OnParamInvisibleSliderMoved`；对应 case RVA `0x138a750` 的直接反汇编在 `0x138a765` 跳到 `0x15fec40`，并以 MOVSS 读取第三个 float32 参数。这支持 HDR UI slot 候选入口的归属，不能把 ARRIRAW 的 ExposureChanged 同名线索拿来替代。

该 case 伪代码出现 bad instruction / halt_baddata，其他输出存在未恢复跳表和间接跳转类型限制；固定 raw 窗口也不是完整主程序、调用链或算法恢复。此处证明入口连接，尚未证明 Global 控件值到序列化值的完整转换，更未连接到像素处理。准入判断依据单字段候选和原生校准闭环，不能依赖这些不完整伪代码补写成功。

### 六帧独立像素复算

独立直接读取六个实际 EXR，每个 24,900,921 字节；核对固定 header、offset table、行号、字节数、B/G/R float32 及采样，并恢复 row-major little-endian RGB。每帧文件/像素 SHA-256、6,220,800 通道的有限值、范围/计数，以及按输入清单重新取的 48 个中心通道值，都与公开 JSON 一致。六帧合计独立读取 37,324,800 通道，没有依赖测量 JSON 的布尔通过字段作为数值 oracle。

| 相对当前无 HDR 分支中性参照 | 变化通道数 | 最大绝对差 | 字面 RGB 字节相同 |
|---|---:|---:|---|
| HDR −1 | 5,832,000 | 0.2938775420188904 | 否 |
| HDR 0 | 0 | 0 | 是 |
| HDR +1 | 5,832,000 | 0.40341198444366455 | 否 |
| HDR 0 重复 | 0 | 0 | 是 |
| 中性恢复 | 0 | 0 | 是 |

另直接核对零档/重复零档的整幅 RGB buffer 相同。四个中性状态的本轮文件摘要也相同；这里的“当前参照”不能扩张为所有工程或前一轮 EXR 文件元数据相同。±1 各只有一帧，重复性证据限零档和中性恢复。

在每档 16 个色块中心的 48 通道上，独立重算“neutral EXR 通道 × 2^档位”的候选误差：−1 为 0.20612257719039917，0 为 0，+1 为 0.5965884923934937。它否证此次 EXR 通道直接乘倍数的候选，不否证另一个已确认线性工作域中的曝光倍增，也不恢复内部 Jz 公式。

输出实际保留超白及近零小负值：+1 最大 1.4034119844436646；−1/+1 最低分别约 −4.64e−8/−1.86e−7。负通道数量与数值幅度须一起报告，不能只用计数推断强负影调作用。所有输入非负，本轮仍没有负输入实验或 alpha 验收。
