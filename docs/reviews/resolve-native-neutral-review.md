# 第三轮原生中性导出与 CDL 对照：独立对抗审查

审查日期：2026-10-13（Asia/Shanghai）。对象：当前第三轮研究报告、两个公开结果 JSON、README、立项书 0.7、MCP 调用器、EXR 读取器，以及本机私有脚本、原始回执、grade 和静态分析记录。

**结论：当前范围没有尚未关闭的必须修改项。** 本轮支持固定实验条件下的中性导出重复、这两份 grade 的应用及恢复，以及有限的 DRX 结构关联。它不使阶段 1A 的原生 HDR 曝光验收通过，也不提供可以移植的原生曝光算法。

本审查只读证据；只写本文件。没有启动或调用 Resolve、MCP、SDK、目标 EXE/DLL，没有修改工程、调色、配置或注册表，没有下载工具。EXR 仅独立读取文件头及文件长度，没有解码整幅图像或重跑测量；未重复大文件摘要与原程序静态扫描。

## 发现及处理

| 严重性 | 状态 | 证据与建议 |
|---|---|---|
| P2：采样范围被写成普遍行为 | 已关闭 | README 原先“这套设置保留 PNG 编码值”可能被理解为整幅、所有格式或颜色管理模式的结论。当前明确限定“16 个色块中心的 48 个采样通道”，与原始测量、主报告和立项书一致。整幅一致描述的是几个输出之间的比较，不能代替整幅输出与输入的颜色解释验证。 |
| P3：成功正文的形状检查不完整 | 已关闭 | 原调用器可能对缺少 `result` 的正文 `{}` 打印成功。当前在打印前明确检查正文为 dict 且 `result` 为 dict，该静态反例会被拒绝。修复只增加形状检查；本轮既有成功回执没有因此形成假成功。新版调用器另做只读状态查询，新回执与两个公开结果中的末次状态逐项一致，源码及回执摘要均已核对。 |

初次 still 导出失败仍保留为失败。RPC 成功并不等于工具脚本成功；原始工具正文含 `error`，重试证据与第一次回执分别保存。不能由该次失败推断 Unicode 路径不受支持。

## 运行记录与操作边界

- 当前公开记录列出的执行脚本、调用器、读取器、原始回执和两份结构分析文件，其小文件长度及 SHA-256 与实际文件吻合。中性原有 12 份回执仍可核对；CDL 后最终状态使用另名回执，没有覆盖中性历史记录。
- CDL 的 setter、重放、恢复和末次状态公开对象逐项等于原始工具正文。三个新增任务 ID 互不相同，固定 `MarkIn = MarkOut = 108000`，格式为 `exr / RGBFloat`；对应 poll 为 Complete / 100%，且没有正在渲染。
- 克隆脚本先确认版本、当前 Disk 测试库、指定原工程、无运行中的渲染和副本不存在，再保存/导出原工程并导入实验副本。调色动作落在 `EXPO_002_NATIVE_HDR_211`。原工程有保存/导出动作；“没有调色改动”不能被扩张为“完全没有状态变化”。
- 渲染脚本只启动本次新建的任务 ID，不删除全部任务，也不调用全局停止渲染接口。重放/控制脚本确认一层、单节点和指定时间线，再使用 `GetNodeGraph(1)`、gradeMode 0、`applyToAllLayers=False`。其证明范围限这个单层静态样本。
- CDL 重放前，脚本先应用中性 DRX，并重新读取节点数、无工具及空 LUT，然后才应用非中性 DRX。末次又恢复中性并保存、导出、渲染。这比只重复应用当前非中性状态更能验证实际重放链路。
- 官方 `run_script` 沙箱提供执行边界；复制工程、设置路径、抓 still、保存、应用 grade 和渲染均有真实副作用。gallery/cache/media 路径返回值及读回支持本轮实验位置，不构成对应用全部缓存、日志或用户库字节的隔离审计，也不证明并发人工操作不能改变当前对象。

当前调用器检查 JSON-RPC error、`isError` 和正文 `error`，仅终止自己创建的 MCP 子进程。故意失败回执确实含工具正文错误；其控制台记录没有成功标志或原始错误内容，只有通用错误说明。stderr 收集线程有等待。审查没有重新执行该失败探针。

成功正文形状修复后的调用器为 3088 字节，SHA-256 `50b9ffe640367013907c9c473f1a5838560571a33a62734194ef01bdd290a265`，与两份公开结果的当前源码条目一致。新增 `post-validation-final-state-result.json` 的摘要及正文已读回核对；此前回执仍保留。本审查没有自行运行查询。

## 像素证据

六个 EXR 各抽读前 4096 字节，并核对长度：均为 24,900,921 字节，magic 20000630、version 2，头结束于 441；无压缩、递增 scanline，dataWindow 为 1920×1080，B/G/R 三通道 float32、1×1 sampling，帧率 30/1。与固定格式读取器的要求一致。[OpenEXR 官方布局](https://openexr.com/en/latest/OpenEXRFileLayout.html)

读取器按 offset table、行号、行字节数恢复平面通道，并核对有限值；当前比较使用 little-endian float32 **字节**，不是 `array_equal` 的数值相等，再与 OpenCV 解码核对。整个 RGB 像素摘要约定为 row-major、little-endian float32。该程序限定当前普通单 part 未压缩格式，不能当作通用 EXR 验证器。

六份私有 measurement JSON 均与公开测量对象完全一致。以下整幅结果来自这些记录及被审查的读取代码；本审查没有重新计算整幅像素摘要或变化通道数。

| 比较 | 可以支持的结论 |
|---|---|
| 初始中性 / 重复中性 / 中性重放 | 三者文件及整幅像素摘要一致，支持固定状态和这份中性 grade 的重复性；不等于 HDR EV=0 或整条颜色链路旁路。 |
| CDL 直接设置 / 先中性再重放 CDL | 两者文件及整幅像素摘要一致；setter 返回 True、像素变化及重放记录相互支持。本样本不验证完整 CDL 数学公式。 |
| 最后恢复 / 最初中性 | 文件及整幅像素摘要一致，支持本次实验的调色恢复；不声称工程所有元数据、still、任务列表或外部状态逐字节恢复。 |

独立用公开样本和输入清单重新计算 48 个采样通道，中性最大编码值误差为 `2.9694545600200684e-08`，与 sRGB 解码线性值的最大误差为 `0.2870986529831294`。CDL 的 10 个灰色块中心最大变化为 `5.960464477539063e-08`，6 个彩色色块中心为 `0.12218957394361496`，与公开记录相同。

这些采样证明该设置下的有限输入输出关系。浮点 EXR、输入元数据 Gamma 2.4、项目名称含 HDR、工作亮度 1000，均不足以证明像素处于场景线性域或已经施加原生 HDR 曝光。

## DRX 与 descriptor 关联

中性 DRX 的文件摘要及两处 `HasCorrection=false` 已直接读回；CDL DRX 摘要及按文本出现顺序的 `true/false` 也一致。Body 编号是文档出现顺序，不能直接命名为某个 node layer。实际 DRX 没有被本审查编辑。

已读取 descriptor 检索和中性匹配的私有记录：39 份 descriptor、401 个 message；203/142 字节 Body 对 VersionBody 的完整递归解释分别计入 60/35 个字段和 16/9 个嵌套消息，各项结构错误为 0。另有 19 个 opaque bytes 兼容候选。`ParseFromString` 和初始化成功只补充结构检查，不能独立证明消息类型、宿主反序列化入口或控件身份。[Protobuf 官方编码说明](https://protobuf.dev/programming-guides/encoding/)

中性的实际值分支为 `int_field`，没有 HDR #16/#17/#18；已检查的身份字段是 uint32，相关 descriptor 没有给出 HDR 参数 ID 的 enum。声明的 nodeparams→Parameter→HDR 路径是 schema 允许承载的路径，尚不是 neutral 实际经过的 HDR 分支。

CDL 增量记录与公开摘要一致：Body0 的结构计数为 126 个字段、49 个嵌套消息，新增 15 个参数；Body1 没有新增参数。参数按容器路径和 key 比较，未用 repeated 列表下标代替身份，节点身份保持。实际新增容器为 `graph.nodes.markstore.marktimelines.marks.mark.params`。其中 `0x06000005 / float_field` 的值及所记录的 little-endian float32 字节解读为 0.75；两个 Body 的实际 HDR #16/#17/#18 数量均为 0。

单次 SetCDL 请求与 0.75 序列化值的关联是有边界的证据。它没有解释其余 14 个键是显式改值还是默认值展开，也没有建立稳定编辑合同、完整 key→UI 映射或未来 HDR 样本存储位置。本审查核对了记录、字段树、计数和小文件摘要，没有重新执行全套解压/descriptor 匹配程序。

## 保留的未验收项

原生 HDR Global Exposure 的 UI 值、参数 key、颜色操作域、旁路/0/−1/+1 和候选公式仍未得到受控行为验证。此次 CDL 对照不替代这些输入。新版 OCIO 的公开公式也不能证明 Resolve 原生控件调用它；旧版本函数地址不能搬到新版。

README、立项书 0.7 和主报告目前均保留阶段 1A 进行中、阶段 1B 未开始及 OpenCut 尚未接入的状态。源码来源/程序完整性的大文件核查由主实验记录提供，本审查没有重做。未验证完整用户库、性能、真实视频、一般多层 grade、官方内部消息类型选择或可发布产品质量；无需为本轮收尾扩展这些任务。
