# HDR Global字段与零值开关独立审查

日期：2026-10-13。范围为默认Global路径的静态字段传递与曝光开关条件；没有新增原生渲染，正式测量仍为42帧。

结论：在报告明确的默认类型、包集合与最后写入者条件下，当前无未关闭P1/P2；这不构成完整曝光公式验收。补充私有独立审查SHA-256：`827ce87be88432977d50d0117a8636effc0cd32f9cea9196397d19ce2db9ba8a`。

## 已完成的局部独立复核

独立审查者只读固定Resolve.exe的必要PE字节、既有局部反汇编及相关记录，没有启动Ghidra、Resolve或目标代码。初轮复核确认：初始化器将第二个浮点实参的32位位型写入参数包首字段；内部类型0分支原样复制到HDR对象偏移48。没有在这段传递中发现倍率、指数或单位换算。

原始指令和常量支持：与零比较时，正常有限非零float32产生不等结果，+0/−0产生相等结果。独立标量计算的14个代表值与分支证明一致，包括最小正常值、极小正常值、±1、±FLT_MAX和带符号零。这不是对全部float位型的穷举；次正规数、非有限值以及未知的MXCSR FTZ/DAZ设置不在结论中。

最关键的边界是：曝光位在类型分派前累积OR，因此所有纳入的参数包都可能置位。零值Global不会清除已有分区带来的曝光标志；Global数值为零也不等价于整条HDR处理关闭。这项限制已经写入[研究报告](../research/hdr-global-gain-binding.md)。

## 上游绑定复核

补充复核支持键`0x86000305`经映射复制、节点偏移96首float、参数包首float，最终在类型0赋值点原样写入G。RTTI确定值对象类型，名称读写方法将对象偏移8关联到`GAINJZ`；名字表的Global枚举6经默认表对应类型0。反编译文本中的整数类型猜测不能推翻原始MOVSS搬运，也不能把这组名称方法称为已经证明的protobuf入口。

原始对象构造器将偏移116处DWORD清零，其中包含偏移117的gain位；之后按52字节遍历全部包累积OR，最后只另写偏移116的整体启用字节。因此正常有限/±0值域内，报告中的gain开关概括适用于这段新建过程。

独立审查同时指出三项必须携带的边界，已写入报告：构建器只遍历输入映射中实际存在的条目；显式node设置可以覆盖类型和禁用条目；未知名字默认查找失败也会回退为类型0且启用，每个类型0都会覆盖G。因此不能把赋值点的绑定扩大为任意完整工程中Global是唯一写入者。公式的`G=E`替换已经明确增加Global包为最终类型0写入者的条件。
