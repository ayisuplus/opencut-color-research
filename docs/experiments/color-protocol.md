# 调色实验与验收协议 v0.1

日期：2026-10-12。所有阈值是本项目的拟议验收标准，不是既有测量结果。

## 本次实际演示

运行 `node experiments/linear-exposure.mjs`。以线性值 0.18 为非负 SDR 灰值输入；线性曝光乘数为 `2^EV`，然后按 sRGB 传递函数编码显示。对照组故意在 sRGB 编码值上乘二。

程序检查 0 档曝光保持 0.18、+1 档变为 0.36，并用固定解析值独立检查两个 sRGB 编码结果：0.18 对应 0.46135612950044165，0.36 对应 0.6342527406021729。这两个常量另用 Python 标准库 Decimal 在 50 位精度下计算，不只检查同一 encode/decode 的往返。结果报告也给出错误路径反推得到的等效曝光，避免把“程序没有报错”当作正确。实测输出见 [结果记录](linear-exposure-result.json)。

公开传递函数依据：[W3C CSS Color 4 转换示例](https://www.w3.org/TR/css-color-4/#color-conversion-code)。实验限定单个灰值，不验证视频解码、GPU、编码、达芬奇或 OpenCut 的行为。

## 为阶段 1A 准备的实测输入

运行 `python experiments/make-exposure-inputs.py`，用本机已有 NumPy/Pillow 生成 1920×1080 的 16 块灰阶与 RGB/CMY 色块，保存到 `experiments/output/exposure-inputs/`。正式输入为 `opaque-srgb16-patches.png`：16-bit RGB、全范围、sRGB 标记、不透明。8-bit preview 只供观看。格式依据 [W3C PNG 第三版](https://www.w3.org/TR/2025/REC-png-3-20250624/#11sRGB)。

[输入摘要](exposure-input-manifest.json) 记录文件 SHA-256、采样中心、量化码值，以及预期线性值和量化后还原值。后续计算以实际码值和明确的颜色解释为基准，不把理想 0.18 当作量化后精确输入。本轮只验证夹具生成及文件结构；尚未验证 Resolve 能按这些约定导入或导出。此夹具没有负值、超白或透明样本，不能用来验收 HDR/alpha。

## 阶段 1：单帧计算

先冻结一个颜色约定。研究基准使用 D65、sRGB 原色、线性 RGB 浮点样例。首组样例输入每通道限定 [0,1]，曝光限定 [-1,+1] EV，因此非裁切输出限定 [0,2]；1.0 是约定的归一化白值。下表的 1e-6 均指该固定样例范围内、每通道以此归一化单位计算的绝对误差 max(abs(candidate - reference))，不承诺任意高亮值下的相同绝对精度。实际视频的解码、范围和矩阵转换尚需宿主实现。

| 检查 | 拟议判定 |
|---|---|
| 默认/旁路 | 固定颜色转换之外不改变像素；f32 参考值误差不超过 1e-6 |
| 曝光 | 非裁切的线性样例 +1 EV 等于乘二，-1 EV 等于减半 |
| 操作顺序 | 含偏移或曲线的两次操作换序，应能观察到预先计算的非等价结果 |
| Alpha | 首期仅不透明输入；接入合成前必须补充直通/预乘 alpha 规则与透明边缘用例 |
| 不支持的输入 | HDR、负值、透明像素、未知传递函数或未约定范围不得静默当首期 opaque SDR 输入；返回明确不支持或要求用户指定 |
| 参数快照 | 同一份参数序列的重复处理输出一致；保存/重载不改变参数 |

数值基准先于 GPU 优化。将来 GPU 结果与 CPU 解析/独立参考比较；阈值按所选纹理精度和算子重新冻结，不能在看过失败后随意放宽。

## 阶段 2：单片闭环

使用自制的 10 秒、1920×1080、30 fps、8 位 SDR 视频及对应无损源帧。记录源时间戳、色彩标签、视频范围、编码方式和摘要。不能只用“第 N 帧”代替时间戳匹配。

1. 同一个解码帧、同一参数快照送进预览和导出；在显示转换与视频编码前、尚未量化到 8 位的工作 RGB 比较。首个闭环限定沿用阶段 1 的样例/参数范围，使用同一调色实现，每通道绝对误差不超过 1e-6。无法取得工作 RGB 时此项仍为未验证，不能用截图代替。扩大域或加入新算子前重新冻结精度标准。
2. 显示转换与视频输出转换分别验证，不直接比较截屏的颜色和视频字节。
3. 先以无损图片序列验证输出变换，再编码视频、重新解码和匹配时间戳。压缩引入的误差另设阈值；当前未冻结码率、编码器及容差，所以这一项尚不能判为通过。
4. 验证源素材未改变、调色开关可旁路、保存项目并重开后参数和输出一致。
5. 在真实宿主测量端到端预览，包括解码、上传、调色、显示。记录 p50/p95 帧耗时、丢帧、显存和测试 GPU。拟议目标为 1080p30 连续 10 秒，无明显交互阻塞；它不是已证明的性能。

## 阶段 3：风格评价

至少使用肤色、天空/植被、高对比夜景三类原创样片。展示旁路与调色的 A/B；分别记录用户喜欢的地方、问题和是否采用。数值正确、格式一致、实时性能与审美通过是四项不同证据。

## 每次实验保存什么

保存版本/commit、素材摘要、颜色约定、操作顺序、参数、时间戳、处理输出、比较结果和未通过项。原始素材与本机采样放在 Git 忽略的 `evidence/local/`；只提交脱敏小样或摘要。素材是软件实验夹具，采用后用于正式创作的媒体再按用户的资产管理习惯归档。
