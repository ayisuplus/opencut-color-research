# HDR曝光：宿主查表路径的静态证据

日期：2026-10-13。新增原生渲染0帧，正式测量仍为42帧。

此前的1024项端点表假设，现在有了相应宿主代码的直接证据：表长、坐标步长、采样设置和常量上传链均已定位。**仍未取得本次实验的运行时表格，也未把界面gainjz完整绑定到宿主标量；完整曝光公式尚未恢复。** 本轮没有修改达芬奇工程或安装文件。

## 已连接的静态链

分析对象仍为已固定的Resolve.exe副本，前后SHA-256一致。REA整文件默认分析此前超时；本轮改用Ghidra已有独立数据库，禁用默认分析，只反汇编选定范围。结果、地址、原始文件哈希和失败记录见[证据清单](../experiments/hdr-host-table-evidence.json)。私有二进制、PTX及反编译结果保留在Git忽略目录，未复制到产品代码。

1. 注册入口通过实际PE导入项调用`__cudaRegisterFunction`，将之前的浮点HDR设备符号关联到宿主启动函数。`__cudaRegisterVar`注册同名92字节常量区；这个宿主符号地址不是设备内存地址。
2. 上游函数将92字节参数通过`cudaMemcpyToSymbolAsync`传给上述常量符号，再经过启动函数调用`cudaLaunchKernel`。由此建立静态调用关系，尚未观察一次原生渲染实际执行该路径。
3. 参数打包函数把宿主对象偏移117的字节扩展为常量偏移16的整数字段，且同一条件关联`HDR_USE_GAIN`标签。它对应此前PTX查表分支的开关；尚不能将开关的所有取值与UI零档/非零档一一对应。
4. 资源准备函数构造六张表。启用的第一张表进入同一对象的资源列表，随后作为设备函数第一个纹理句柄传入。此项属于静态资源顺序与实参追踪，未读取运行时纹理。

## 表长与采样设置

表格生成函数分配并处理1024个float元素；资源准备处也出现1024×1的尺寸实参。第一张表的坐标步长常量为`0x3c802008`，即`float32(16/1023)`，偏移为−8。加入全局标量及分区贡献后，表格还要经过平滑处理，不能略掉这一步称作最终原生表。

采样器路径通过真实导入的`cudaCreateTextureObject`创建资源。核对调用实参、枚举映射数组及本机CUDA 12.8头文件后，得到：线性过滤、归一化坐标、前两个寻址维度为Clamp；第三维保留默认0。以上描述仅针对所追踪的静态分支。

这使原先的表长与采样配置假设得到支持。归一化线性纹理的半texel坐标、插值精度等公开定义见[NVIDIA CUDA线性过滤](https://docs.nvidia.com/cuda/archive/12.8.1/cuda-c-programming-guide/index.html#linear-filtering)。公开定义不能替代Resolve运行时证据。

## 对公式的约束

用G表示宿主对象偏移48处的全局标量、Z表示分区产生的逐项贡献。在平滑前，第一张表的结构可概括为：

`T_pre[i] ≈ −8 + 16*i/1023 + G + Z[i]，i=0…1023`

这里的近似号明确保留float32运算与舍入；G到UI曝光值E的上游映射尚未证明。生成器包含分区叠加及修正，不能无条件设Z为0。随后对表进行均值平滑，调用比例为float32(0.1)；1024项时形成103点窗口，内部半径51，边缘按对称可用范围缩短。原始SSE指令显示累加和除法采用float64，结果转回float32；反编译文本的float类型推断不足以判断实际精度。还需验证完整参数状态。

结合之前的设备分支，候选结构为`q=log2(clamp(Y,0.0703125,4608)/18)`，归一化坐标`u=(q+8)/16`查平滑后的表t，再将三个工作通道共同乘`2^(t−q)`。这里的Y是设备工作通道，**不是导出RGB的G通道**。输入/输出颜色变换、其他启用分支以及近似设备算术仍属于完整模型的一部分。

若另行假定G=E、Z=0、理想精度、内部采样区间，则对称均值保持直线，得到此前的条件倍率`2^(E+q/1023)`。它说明残差机制为何值得追查，并不是已经验证的最终曝光公式。

## 数值反例也保留

本轮沿用旧48通道、冻结BT.709候选和亮度系数，检查端点表及平滑的数值效果，没有增加逐色块拟合参数。首次float32累加候选经独立原始指令审查被否定；改用float64累加、float32写回后，主要残差仍保留：

| 同一旧+1样本，最大绝对误差 | 结果 |
|---|---:|
| float32端点表、理想插值、未平滑 | 1.005931365e−5 |
| float64累加和除法、float32写回、理想插值 | 9.889709238e−6 |
| float64累加、float32写回、插值权重取最近1/256 | 1.383666187e−5 |
| 已否定的float32累加候选、理想插值 | 2.159247271e−5 |

这些是事后候选检验，不是GPU逐位模拟或盲测。当前不能把残差归因到单一浮点误差，也不能宣称平滑已经解释全部像素。原始候选及其限制继续保留在[前一轮报告](hdr-static-texture-candidate.md)，其历史结果未改写。

## 方法纠正与下一步

Windows展开信息可能把同一函数分成多个链接区间，不能把每个区间当成独立函数。已核对CHAININFO并修正浮点上传函数的范围。一次相邻函数探查越过边界，Ghidra报告重叠错误，即使外层批处理返回0也不算成功；纠正范围后取得成功结果。解释以原始指令、导入表和明确参数传递为准，反编译器推断的类型仅作辅助。

下一步优先追G的上游来源与零档开关条件，再固定不等幅混色和空间重复夹具做未见样本验证。还缺实际工作颜色变换、原生运行路径、边界条件及其他颜色环境；本轮不扩大“完整公式”的结论。[独立审查](../reviews/hdr-host-table-review.md)记录复核范围。
