# 三个未见 Global 存储值的原生对照

日期：2026-10-13。阶段 1A。观测前固定的曝光模型成功预测了 −0.5、+0.5、+2 三档，主模型最大采样及 ROI 通道误差为 2.98023224e−7，低于预定 1e−6 门。没有修改预测、调整阈值或拟合参数。新增六张原生 RGBFloat EXR，正式测量累计 54 张。这里只检验原混色夹具上的三个新参数值，尚未验收完整 HDR 公式或真实运行后端。

## 原生实验与控制

用户关闭偏好设置后，官方接口重新提供版本 `21.1.1.10` 和专用库 `OC_COLOR_001_TEST` 的有效身份读回；此前空库／页面回执继续留存，没有证明空值的原因。先备份 005，以已完成的 006 归档导入独立 007，保留源 005 的全部冻结设置、素材对象和 23 个已有任务。实验只在 007 中运行，顺序为：无 HDR 中性、−0.5、+0.5、+2、+0.5 重放、无 HDR 中性恢复。

每一档在渲染前通过严格 DRX 读回；两个中性档各 45 项，四个非零档各 51 项，共 294 项检查。独立递归解析也确认指定 Global gain、其他 Parameter 的完整 wire 字节、两个 Body 和固定外层元数据白名单。三份私有源 grade 只变更已校准的 Global 四字节存储值，没有新增 UI 或物理 EV 校准；中性控制是无 HDR 分支，不是新测的 HDR 精确零。

第一帧的十六个 480×270 色块覆盖整幅 1920×1080 图，其 6220800 个 RGB 通道与预先固定的 `float32(U16) * float32(1/65535)` 逐位相同。每张 EXR 均以独立 scanline 解码和 OpenCV 交叉核对全部通道。只创建并单独启动六个新 owned job，前档 Complete100 且 idle 后进入下一档。

+0.5 重放与首次 +0.5 的整幅 RGB 原始位相同；中性恢复与首次中性也逐位相同。这两项是全图控制，主模型误差门则限定中心和 ROI，两者不可混称整幅模型等价。

## 门失败与项目恢复

复制脚本初稿缺少部分对象／完整读回守卫，未执行即在独立预审中修正。两次中文路径传输编码失败发生在 native 脚本执行前；随后使用语义相同的 ASCII 转义脚本完成导入，保留初稿和失败回执。

首中性 DRX 门在渲染前发现旧模板把两个 Body 的端点都固定成 `[1,2]`，而实际空 Body1 保留源 `[2,3]`。独立全字段核查后，仅限定 Body0 的十处 typed ID 映射，Body1 零映射并要求精确 `[2,3]`；完整 Parameter／未知字段／外层守卫保持。失败和准入修正版分别留存，未改像素模型或冻结输入。

六帧完成后 007 保存并导出归档；初次 finalizer 在随后加载 005 时停止：项目和时间线 getter 仅 `perfCacheClipsLocation` 从冻结相对路径 `CacheClip` 解析为绝对路径，其余各 157 项设置、263 项素材属性、clip 身份、时间码、节点 getter 和 23 个任务／状态全部相同。只恢复这一缓存键，经独立准入的官方脚本在保存前后均核查原冻结快照匹配。最终 005 已保存且 idle，007 归档保留；恢复范围是这些已捕获 getter 和对象，未宣称整个应用或全部不可见调色状态逐字节恢复。原失败 finalizer 不记成整体成功，归档的导出控制流与后续成功恢复各有单独回执。

[分析器](../../experiments/analyze-hdr-unseen-gains.py)把旧失败后的导出证据、新恢复回执、实际六帧摘要、严格读回和原预测分别绑定，拒绝覆盖结果文件。冻结输入和误差门先于新输出，结果分析不调用 Resolve 或 GPU。

## 结论与下一步

当前固定条件下，单 Global、非零、空分区的候选不再只解释已有 ±1 样本，也能预测三个未见存储值；这是有限的前瞻行为证据。实际 Gamma／矩阵／资源／后端仍未捕获，自有高 0 一维 CUDA array 与静态高 1 资源差别仍保留。颜色仍是旧夹具，UI 连续换算、黑场偏移、非空分区及整个浮点输入范围均没有由本轮证明。

下一项优先检查低亮度夹紧与表端点：先用当前冻结模型确定哪些新输入能区分候选，再冻结新的颜色夹具和预测，通过独立准入后才做原生观察。先保持黑场偏移零、Global 单控件和同一颜色条件，避免把多个未知因素同时改变。若官方接口无法记录必要状态，再请求一次明确的人工操作。尚不开始 OpenCut 产品调色集成。
