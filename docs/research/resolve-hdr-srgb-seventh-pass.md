# HDR 第七轮：sRGB 条件的原生 −1 / 0 / +1 配对

2026-10-13，Resolve 21.1.1.10。接续[第六轮关闭重开实验](resolve-hdr-context-sixth-pass-b.md)，完成五张新 EXR RGBFloat 和三份原生 HDR grade 读回；正式测量帧累计32张。

**结果：** sRGB 条件的 stored Global −1、0、+1 都经过实际 grade 应用、项目关闭重开、浮点导出和严格参数读回。零档与无 HDR 中性参照逐位相同；+1 与第六轮 sRGB +1 逐位相同。负档补足后，五个固定逐通道候选仍有误差，原 Rec.709 条件中接近4的 BT.709 解码正负档比值，也不能推广到这个 sRGB 条件。

这是内部存储值的实验，执行时没有新增005的控件显示或 palette 菜单见证。后续用户已确认当前中性Rec.709状态下两项菜单均为「使用时间线」，范围见[005菜单见证](resolve-hdr-005-menu-witness.md)；该观察不回填先前渲染状态。完整公式、任意 UI 换算和颜色上下文的内部解析仍未知。

同一自有1920×1080 PNG16、YRGB、单层单节点、空 LUT、时间线帧108000。四张 sRGB 帧仅按顺序应用无 HDR 中性、固定 −1、固定0、固定+1 grade；最后回 Rec.709 应用中性 grade。每帧都先设置 Gamma、保存、明确关闭并重开005、重设三条研究路径，再核完整 p/t 设置、clip、两个身份、timecode、节点/层和预期工具。零档的工具为None，仍实际执行了 GrabStill 和 DRX 导出，没有把它跳过或重命名为无 HDR 分支。

[执行前独立审查](../reviews/hdr-srgb-pair-review.md)发现并关闭一个P2：最后一帧后也必须核已有任务完整对象及全ID集合，不能只看完成状态。准入执行器 SHA-256 为 `7b61da88d29e572869910d63633b04f3d14d06cf63cb021d2f513b0a76113cca`，计划为 `f4dbd8618d1179336336c62552d530763177e765b33cf6e3ebcc7ee919a02e9f`；执行前实际离线组装并编译19个SDK脚本，不包含原生调用。

项目关闭重开不是整个程序、GPU或缓存冷启动；路径每次重设，getter检查不等于文件系统缓存审计。源恢复检查也不等于全部工程 grade 字节或全应用状态审计。

## 三份实际参数读回

独立严格解析器按固定39个descriptor文件、401个消息定义检查两Body的字段、wire、required、oneof、完整消耗和动态初始化。三个档位都通过；没有unknown或其它严格错误，节点身份相同，HDR #17/#18计数为0。

- −1、+1：唯一HDR #16 / Global `gainjz` 的float32精确为输入值；全部Parameter原始及canonical字节、HDR存在性/默认与各自固定来源相同。
- 零档：来源DRX显式存储float32零；原生读回省略这个字段，保持同一HDR #16 / Global及饱和度1。该字段是proto3无独立presence的标量，默认0；Body0由86个已知字段/284字节变为85/279。仅允许这一个零标量的省略，其他参数和节点保持；canonical语义相同，但原始HDR Parameter字节不同。
- 三档的完整VersionBody清除lastmodtime后，canonical字节均与各自来源相同。外层图像及元数据变化另存；零档像素与中性相同，不证明两种grade结构相同。

## 同一候选跨档位仍不成立

使用[已冻结的公开传递函数](hdr-exposure-domain-primary-models.md)，逐通道预测 `encode(decode(neutral_EXR) × 2^stored_gainjz)`，不拟合参数。[三档候选结果](../experiments/hdr-srgb-pair-candidates.json)只使用本轮实际−1/0/+1和无HDR中性，不借用旧Rec.709负档。

| 固定候选 | −1最大通道误差 | +1最大通道误差 |
|---|---:|---:|
| 直接EXR通道缩放 | 0.1899592876 | 0.5744007826 |
| 纯Gamma2.4 | 0.05919437000 | 0.09075984008 |
| OCIO video1.83 | 0.03776483699 | 0.05427918964 |
| sRGB分段 | 0.04539781462 | 0.07234364810 |
| BT.709舍入常数/固定Colour逆式 | 0.01977496819 | 0.03245493025 |

零档候选的数值往返误差不超过 `1.1102230246251565e−16`，这不是非零档公式通过的证据。

对中性、负档、正档均为正的36个通道，本轮 `D709(+1)/D709(−1)` 范围为 `4.322951536729126…15.280799387983336`，离4的最大差 `11.280799387983336`；`2D709(−1)` 与 `0.5D709(+1)` 的最大差为 `0.07731003931107061`。sRGB解码候选的同一比值为 `5.199147162382761…20.694772875987073`。这些是各假定解码函数下的有限样本算术，不能解释成物理EV；近黑比值对小分母敏感，须同时查看上述绝对残差。

相比之下，第五轮原Rec.709条件中，BT.709非零档配对比值离4的最大差约 `2.139e−6`。本轮只说明该关系对新条件不成立，没有证明哪一个内部环节造成差异，也不因 `gainjz` 字段名而认定JzAzBz算法。

005当前菜单已取得人工确认。下一步需把菜单状态与非零grade、Gamma切换和重开操作绑定，核对node与项目条件的解析关系，再设计能区分转换位置的实验。阶段1A继续；这些数据尚不足以固定OpenCut的HDR曝光实现公式。
