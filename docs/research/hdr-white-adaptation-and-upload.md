# HDR 白点适配矩阵与上传路径

日期：2026-10-13。阶段 1A 继续。固定静态路径中的默认白点适配使用 Bradford 形式，但存储的逆矩阵只保留四位小数；同白点条件不能省略这个矩阵。将这一固定候选放入此前的自有 GPU 程序后，已有灰阶、纯色、混色的最大采样误差降至 2.636e−7，已配置 sRGB 的两档共 96 个采样通道完全一致。完整运行公式尚未验收：本轮没有新增原生画面，也没有捕获 Resolve 实际矩阵、纹理或后端。

## 矩阵发现

独立读取固定研究副本并核对有界函数、常量、模式选择、行列布局、双精度复制和矩阵运算。默认候选的色度为 Rec.709 原色与 D65 白点。矩阵 C 的公开名称和适配形式依据 [ICC Technical Note 02-2003](https://www.color.org/chadtag/)；存储精度和具体静态路径是本机研究发现。

```text
C = [ 0.8951   0.2664  -0.1614
     -0.7502   1.7135   0.0367
      0.0389  -0.0685   1.0296 ]

B = [ 0.987   -0.1471   0.16
      0.4323   0.5184   0.0493
     -0.0085   0.04     0.9685 ]

A = B · diag((C·Wt)/(C·Ws)) · C
```

独立有理数求逆确认，B 的九个元素均等于 C 的精确逆矩阵分别四舍五入到四位小数，B 并非精确逆。`max|B·C−I|=7.905e−5`，`max|C·B−I|=1.0082e−4`。白点向量是 3×1 的 double 列向量；九个元素按行写入 double 矩阵，材料化不额外转置或降精度。适配函数没有相同白点就返回单位矩阵的快捷分支。

默认源白点 `Ws=(.9504559270516716,1,1.0890577507598784)` 来自 xy=(.3127,.329)。固定目标字面量 `Wt=(.95045592,1,1.08905775)` 在此条件匹配八位小数截断，不能据此推广到所有白点生成过程。此时 `max|A−I|≈7.9052992947e−5`，主要来自 B 的存储精度。该数值是矩阵代数诊断，与输出画面的误差不是同一种量。

设 M 是以公开原色 xy 和 Ws 构造的 double RGB→XYZ 矩阵。在已核查的 Gamma 类别分支为假、适配启用、默认色域选中的条件下：

```text
F = F32(100 · A · M)
R = F32(inverse(A · M) / 100)
```

倍率是调用处直接读取的 double 100。正反两端分别构造适配后的 double 矩阵，逆端对其求逆，再将九项按行转为 F32；不能用 `inverse(F)` 代替 R。具体时间线是否进入这个分支，仍没有实时见证。

## 当前可计算的条件模型

与[前轮颜色链](hdr-color-transfer-chain.md)、[表生成与采样](hdr-table-and-sampler-precision.md)组合，当前自有程序的非零 Global、空分区、黑场偏移零模型是：

```text
w = D709(Pp(DΓ(x)))
z = F · w
q = log2(clamp(zY, 0.0703125, 4608) / 18)
u = (q + 8) / 16
t = normalized_linear_clamp_texture(TG, u)
k = exp2(t − q)
y = EΓ(Pa(E709(R · (k·z))))
```

`P` 保留符号；Γ 解码/编码仍按三组的 0/0/5 固定假设。此记法中 p≈0.4166666667、a≈2.4；D709/E709 为对应的分段传递函数。实际程序用 F32 矩阵乘与指定 FMA 顺序、近似指数及对数；这段数学记法没有表达每一次舍入。精确零在已观察的条件旁路，不能让上式自动代替零分支。

TG 是 1024 个 F32 值的自有重建：端点坐标覆盖 −8 至 +8，叠加存储 Global 值，再依已核查的空分区路径处理；内部区域为最多 103 项的中心平均，端点缩小窗口，double 求和和除法后回存 F32。纹理半 texel 坐标和硬件权重精度会影响结果，因此不能将其简化为对编码 RGB 直接乘 `2^曝光`。本轮只复用此前 −1/+1 两张表，没有证明任意参数、非空分区或异常输入。

## 单次自有 GPU 对照

[准备器](../../experiments/prepare-hdr-adapted-gpu.py)在运行前冻结新矩阵；没有拟合像素参数。复用此前已经核查的[CUDA 源码](../../experiments/hdr-transfer-gpu-probe.cu)和同一个可执行文件。输入的实际变化仅 32 字节，全部位于允许的 72 字节矩阵区间 `[8212,8284)`；头、两张表、48 个 RGB/Gamma 记录与模型顺序完全不变。

一次运行仍为 RTX 5090、compute 12.0、CUDA runtime 12080、driver API 13040，输出 3840 个有限 F32 trace 值。两种矩阵乘两种插值乘两档曝光形成 8 种模型，比较三组各 16 个已有色块，共 24 行、1152 个 RGB 预测。这些是已有观测的事后模型检验，不是新的未见画面测试。

独立输入审查用有理数重算全部 18 个 F32 矩阵载荷，逐位匹配；独立输出审查用标量解析重算 1152 个预测和 48 个统计量，全部通过。审查并不把相近像素解释为捕获了真实资源。

## 静态上传证据与实际资源局限

有界材料支持资源重建分支中的第一个 Global 表描述：形状为 `[1024,1,1,1,1024,1]`、datatype 0、storage 3；staging 4096 字节 `memcpy`，不额外转换数值。对应的 channel descriptor 为单通道 32-bit Float，sampler 条件路径选择 Array、ElementType、normalized linear/clamp。datatype、storage、CUDA channel kind 属于不同枚举，不能把 storage 3 当作 channel kind 3。

增量独立审查结合完整 CHAININFO 区间、原始跳表块与导入表，确认当前深度 1 条件分支调用 `cudaMallocArray(R32F, width=1024, height=1, flags=0)`；复制为 `cudaMemcpy2DToArrayAsync`，源 pitch 与宽度字节数均 4096、高 1、HostToDevice、上下文 stream，目标首 plane 的 array 句柄。这里只闭合这个形状和分支，未泛化到 padding、其他 provider/storage/adopt 或 cache-hit 匹配语义。

自有程序使用默认高 0 的一维 CUDA array，两者资源 rank 不能直接等同，数值匹配也不能填补这个实际绑定缺口。资源准备还可在已有资源条件下早退，不能写成每帧都重新上传。实际选择的设备分支、是否重建、源表内容、矩阵载荷仍没有捕获。分配器的有界清单计 269 条已列指令，尚遗漏跳表的三小块；审查者用固定 PE 原始字节另外核实当前 datatype 0 分支，不能声称清单本身覆盖所有分配器指令。

此前有界抽取漏掉叶函数返回、跳表片段与复制函数 CHAININFO 后续区间，均保留初稿并追加修正版；一个 Java 归档命名导致的编译失败也保留。独立复核曾报告错误的调用地址，后以原始 E8 目标校正。结论采用修正的完整材料；Ghidra 退出码本身不作为抽取成功证明。反编译、私有二进制和调色载体均留在忽略的研究目录。
