# 完整float32 GPU参考对照

日期：2026-10-13。阶段1A继续。自有程序在本机RTX 5090上执行了颜色转换、矩阵、曝光查表及返回编码的条件模型；剩余误差没有消失。当前结果不支持把约1e−5的原生残差直接解释为此前使用双精度计算。本轮没有操作Resolve或新增实验帧，正式EXR累计48张。

## 固定模型与执行

[CUDA程序](../../experiments/hdr-transfer-gpu-probe.cu)使用此前公开的数学顺序：源Gamma解码、默认方向转换、工作矩阵、亮度生成q、1024项曝光表、共同倍率、返回矩阵、默认反方向转换和源Gamma编码。表是自有重建；矩阵是固定公开Rec.709/D65色度推导，不读取目标内存。源Gamma枚举仍假定为0/0/5，类别倍率假定1。

[准备器](../../experiments/prepare-hdr-transfer-gpu.py)冻结三组各16个已有中性RGB及−1/+1两张表。两种矩阵路径分别为圆整亮度权重加RGB共同倍率、公开xy推导的XYZ矩阵及逆矩阵；两种插值分别为自有FLOAT一维线性夹取纹理、软件float32理想权重。八种模型共享输入，未拟合参数。矩阵模式同时改变亮度权重和矩阵往返，不能作为单独改变矩阵舍入的实验。

首编译失败：不存在`__exp2f`名称，默认C++模式要求静态断言说明。修复后使用自有单条`ex2.approx.ftz.f32`包装及断言说明，保存旧源、旧准备器与旧冻结。两版9052字节输入完全相同，第二版记录新代码摘要。该指数指令的语法和近似语义核对官方文档。[NVIDIA PTX 8.7](https://docs.nvidia.com/cuda/archive/12.8.1/parallel-thread-execution/index.html#floating-point-instructions-ex2)。没有把失败编译计为GPU执行。

实际单次运行：RTX 5090、compute 12.0、CUDA runtime 12080、driver API 13040；已有nvcc 12.8.61/MSVC工具链，编译参数`-arch=sm_120 -O2 --fmad=false --ftz=true`，显式FMA保留。输出15380字节，包含8×48×10个有限float32值；记录工作RGB、q、u、表值、倍率及输出RGB。这是自有单内核运行，并非目标多阶段执行或实际后端见证。

## 结论与下一步

这次排查只否定“当前固定数学假设换成这套完整GPU/F32程序即可解释残差”。它没有排除其他实际float32顺序、转换分支或设备路径；输入来自中性输出观测，真实内部输入、矩阵、Gamma枚举、纹理资源和表内容仍未捕获。单内核编译优化、目标阶段间舍入及边界行为也未绑定。−1/+1覆盖有限非负输入，不能外推到精确零旁路、负输入、NaN/Inf或其他HDR分区。

下一步优先确认真实后端与资源配置、核对矩阵/表的生成和传递。已有“偏好设置→系统→内存和GPU”的只读询问仍待用户答复，不能用本机自有CUDA运行替代Resolve模式见证，也不能追溯认定旧帧的后端。继续做可独立完成的定点静态核查；在新的区分性假设与冻结前不重复原生渲染或拟合逐色块参数。完整曝光公式及OpenCut算子规格尚未验收。
